# Hermes Factory project rules

- Target native Windows first. Do not introduce WSL, Docker, tmux, bash, or POSIX-only assumptions.
- Hermes is the sole agent runtime. Reuse Hermes profiles, sessions, skills, memory, and authentication rather than duplicating them.
- Preserve Windows paths exactly and test paths containing spaces.
- Treat repository artifacts and SQLite records as authoritative; terminal text and agent claims are observations only.
- Implement vertical slices with strict test-driven development: write and run a failing test before production code.
- Verify every process-management change with real execution on Windows.
- Never terminate a process unless it was started and recorded by Hermes Factory.
- Keep the MVP small: one rig, one seat, lifecycle commands, durable state, then expand.
